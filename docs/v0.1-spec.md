# Neodermo v0.1 spec

This file is the product spec for v0.1. Current `main` shows what has been implemented.

## Product

Neodermo is a mobile-first wound-care journal: Patient → Wound → Assessment, with optional photos and a login. Only observation time is a required clinical assessment field. Establishment and room are navigation requirements, not clinical data. The nurse decides what else to document.

Develop and demonstrate with fictional cases. Real nursing usefulness is the product intent. This is a learning project, not a clinical system.

v0.1 is a time-boxed local desktop browser cut of that product. No phone testing, native tooling, AI, or public hosting in this release. Keep the Flask HTTP/JSON API and data model reusable for a later Android client. React web screens do not automatically become that client.

## Records

| Record | Fields |
| --- | --- |
| Patient | Generated UUID and readable reference; establishment; room and optional bed; optional age in years, weight in kg, sex, and allergies; when age/weight were recorded; active/closed; creation time |
| Wound | Generated UUID; patient ID; optional placement, treatment start date, and wound type; open/closed; creation time |
| Assessment | Generated UUID; wound ID; observation date/time; optional evolution, observations, care performed, expected outcome, and later one photo storage key; server creation time |

- Evolution is improved / unchanged / worsened, with no default. Blank means not recorded.
- Allergies distinguish not recorded, no known allergies, and recorded allergies with details. Empty never means none known.
- Show the previous assessment's expected outcome beside a new form. Do not copy prior findings into new fields.
- Saved assessments are append-only. Closed wounds cannot receive assessments. Closed patients cannot receive wounds, assessments, or context edits. No reopening in v0.1.

## Room and identity

The generated case reference owns the history. The room number does not. Location includes establishment. Distinguish shared-room occupants by bed and generated reference. Closing a case frees its bed and makes the case read-only. A new occupant always gets a new case ID and empty wound history.

Do not store patient names, initials, birth dates, addresses, hospital patient identifiers, or identity mappings in forms, APIs, or database fields.

## Privacy and security

- Authenticate every care-data API. UUIDs are not access control. Auth ships before care-data HTTP routes.
- Credentials, session secrets, the runtime database, and private uploads stay out of Git.
- No analytics or external AI in v0.1. Do not log narratives, assessment bodies, room/bed values, credentials, or tokens.
- No case data in `localStorage`, IndexedDB, or service-worker caches.
- Photos are optional, one per assessment, stored privately and served only through an authenticated endpoint. Metadata stripping does not make a picture anonymous.
- Testing uses fictional cases and non-patient fixture images only.

## How work is completed

Land work as focused PRs. Done means merged to `main` plus verified scoped behavior. A schema migration or tested API is valid work even without a UI. Run the app at its current stage. Do not ship broken controls or defer security behind a public endpoint.

The app is implemented to learn Python/Flask. Agents explain, guide, and review unless explicitly asked to code, and then only the requested change.

## v0.1 exclusions

Android, PWA, native wrappers, camera capture, offline sync, AI/dictation/MCP, public hosting, PostgreSQL, Redis or background jobs, multi-user or role management, exports, general attachments, body maps, catalogues, measurements, pain scores, charts, clinical advice, image analysis, multi-photo editing, and saved-assessment editing. Docker packaging is optional and not a prerequisite for earlier PRs.

## Later, not now

Next: Android access to the same backend, which is the intended client. Then: AI-assisted entry that proposes editable fields the nurse must save. Later: authenticated MCP tools over the same application logic. No AI diagnosis or treatment recommendations.
